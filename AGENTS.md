# AGENTS.md

Prompt Warfare is a server-authoritative 3D voxel battle royale: React 19 + Babylon.js client, Express + `ws` server, and catalog-resolved weapons/map events. Gemini is an offline content tool only; the running server never calls it. It is a single package; player-facing text is Brazilian Portuguese.

Production topology: the static client is hosted on Vercel and the API + WebSocket run on a VPS. Local dev remains a single process with both on the same origin. See `docs/DEPLOY.md` before changing URLs, CORS, or deployment config.

## Commands

- Install: `bun install` (only `bun.lock` is committed; there is no `package-lock.json`, so `npm ci` will not work). Without Bun, use `npm install --legacy-peer-deps`; plain `npm install` fails because root `esbuild@^0.25` conflicts with Vite 8's peer `esbuild@^0.27 || ^0.28`.
- Dev: `npm run dev` runs one process on port 3000: `tsx server.ts` starts Express, WebSocket `/ws`, and Vite middleware. There is no separate frontend dev server.
- Typecheck: `npm run lint` is only `tsc --noEmit` despite its name. No ESLint, Prettier, or CI is configured.
- Tests use Node's built-in runner and run offline in ~1 s:
  - all: `npm test` (alias for `node --test`)
  - one file: `npm test -- server/roomManager.test.ts`
  - one test: `node --test --test-name-pattern "100-point" src/shared/logic.test.ts`
- Content pipeline: `npm run demand:seed` (initial synthetic demand), `npm run ledger:report` (demand/gaps; `--days N` for a window), `npm run loop:report` (demand × usage × catalog version, with closed/persistent/regressed gaps), `npm run catalog:candidates -- --limit 10` (offline candidates), `npm run catalog:dedupe` (semantic near-duplicates), `npm run assets:check` (asset manifest/CDN URLs), `npm run assets:import` (converts the `material/400 Sounds Pack` into `content/assets/files` and updates the manifest/credits; needs ffmpeg), `npm run catalog:promote -- --ids <id> --version <versão>` (validate/publish), `npm run usage:report` (quality/usage), `npm run ledger:prune -- --days 90 --redact-prompts` (retention), `npm run catalog:build -- <versão>` (regenerate procedural base while preserving promoted items; `--reset` discards them).
- Production (all-in-one): `npm run build` (client-only, outputs `dist/`) then `NODE_ENV=production npm start`. In PowerShell: `$env:NODE_ENV='production'; npm start`. Without `NODE_ENV=production`, `npm start` boots Vite middleware instead of serving `dist/`.
- Production (Vercel + VPS): Vercel builds/deploys the client via `vercel.json`; the VPS runs `NODE_ENV=production SERVE_CLIENT=false npm start` and needs `CORS_ORIGINS` set to the frontend origin.
- `npm run preview` is plain `vite preview`: it serves the built client without API/WebSocket, so the game will not connect. Use `npm start` to check production.
- Requires Node 22.18+ (native TypeScript execution; verified on Node 26). `npm run clean` removes `dist/` and `server.js` and works on Windows.

## Runtime architecture

- `server.ts` is the only entrypoint: CORS/preflight, REST (`/api/health`, `/api/metrics`, `/metrics`, `/api/rooms`, `/api/catalog`, `/api/assets`, `/api/ai/preview-weapon`), WebSocket `/ws`, then optional client serving. `HOST` controls the bind address; `SERVE_CLIENT=false` makes it API-only. `/metrics` is Prometheus text exposition and must stay internal.
- `server/roomManager.ts` is authoritative for all match state: rooms, 20 Hz tick (50 ms, `dt = 0.05`), movement, voxels, projectiles, loot, bots, events, and broadcasts. Each match gets a deterministic `contentPool` from `server/contentPool.ts`; prompts resolve against it, and `pool_miss` is recorded separately from a catalog gap. Composed events carry `components` and activate every component. WS messages are JSON `{ type, payload }`; add new client message types to its `handleClientMessage` switch. Rooms are in-memory only—restarting the server discards them.
- `src/App.tsx` is the client controller; it sends `player:input` on a 45 ms throttle and renders `room:tick` / `voxel:deltas`. Never trust client-computed state on the server. API/WS URLs are built in `src/shared/endpoints.ts` from `VITE_API_URL` / `VITE_WS_URL`; empty means same-origin.
- `server/catalog.ts` loads `content/catalog/catalog.json` at boot, exposes `getCatalogVersion()`, and resolves prompts deterministically by aliases/tags (`resolveWeaponFromCatalog`, `resolveEventFromCatalog`). Weak or ambiguous matches return `strategy: 'partial'` and count as gaps; composable capability pairs return `strategy: 'composition'`. Resolvers accept `allowedIds` for the room pool, and `poolMiss` marks a catalog item excluded by the pool. The catalog is read-only at runtime, uses `schemaVersion: 3`, and items carry `status`/`provenance`/`introducedIn`; deprecated items are skipped by the resolver. `CATALOG_WATCH` (default on) reloads the JSON atomically without restarting matches; `SIGHUP` forces a reload. To change content, regenerate the JSON with `npx tsx tools/build-catalog.ts` (or the offline AI tool) and deploy a new version.
- `server/ledger.ts` writes an append-only `prompt_events` SQLite ledger (`node:sqlite`, default `data/prompt-ledger.db`, `PROMPT_LEDGER_DB_PATH`) by default; `server/ledgerPostgres.ts` + `server/ledgerFactory.ts` provide the optional Postgres backend (`PROMPT_LEDGER_BACKEND=postgres`, `PROMPT_LEDGER_POSTGRES_URL`/`DATABASE_URL`, driver `pg` loaded dynamically). It records opened/submitted/cancelled/timed-out phases, actor type, canonical prompt, resolved item, strategy, catalog version, pool hash/miss and timing. Writes are queued and flushed every ~100 ms; never do a synchronous DB write in the 20 Hz tick.
- `server/ledgerReport.ts` aggregates human demand, gaps and abandonment. `tools/ledger-report.ts` writes `content/reports/demand-*.json/.md`; `server/loopReport.ts` + `tools/loop-report.ts` join demand with usage and catalog versions; `tools/seed-demand.ts` writes the initial synthetic demand report; `tools/catalog-candidates.ts` generates offline candidates; `tools/promote-candidates.ts` validates and publishes a new catalog version and merges aliases into existing items. Human approval is required before promotion.
- `server/assets.ts` loads the read-only `content/assets/manifest.json` (textures, sounds, effects, waypoints). Catalog items reference asset IDs; `assetVersion` is sent in `room:init`/`room:tick`. The client fetches `/api/assets`; weapon sounds use `sfx:weapon:*` and event markers use `waypoint:event`. `server/usageReport.ts` aggregates `content_usage` (`equip`, `kill`, `damage`, `survival`, `event`, `feedback`) into `content/reports/usage-*.json/.md`. `tools/ledger-prune.ts` handles retention/redaction.
- `tools/aiGenerator.ts` is the offline Gemini tool (`gemini-4-hydrogen`, structured JSON). It is not imported by `server.ts` or `server/roomManager.ts`; the server boots without `GEMINI_API_KEY`. AI output is untrusted and must pass through `src/shared/budget.ts` validation/clamping.
- `tools/blueprintDb.ts` is the offline SQLite cache for the AI tool (`node:sqlite`) at `data/voxelforge-blueprints.db` (override with `VOXELFORGE_DB_PATH`). It is not part of the runtime.
- `src/shared/` is the shared layer used by the browser and/or server: `budget.ts` (100-point balance, RLE, fallbacks), `prompt.ts` (normalização/canonical key), `voxelWorld.ts` (deterministic island generation, raycast, movement, destruction), `botBrain.ts` (server-driven bots), `controls.ts`, and protocol types in `types.ts`. Keep it free of DOM/Node-only APIs. `src/engine/` is browser-only Babylon rendering; voxel meshing runs in `greedyMesher.worker.ts` and emits `matId` per vertex for `chunkDetailPlugin.ts`. Áudio espacial e VFX ficam em `src/engine/audio/` e derivam de mensagens já existentes (sem protocolo novo). Traversal (sprint/slide/mantle/escada/tirolesa) é autoritativo em `server/roomManager.ts` + `src/shared/voxelWorld.ts` (MAT.LADDER e `IslandMeta.ziplines`).
- Human-facing docs live in `README.md`, `docs/ARCHITECTURE.md`, `docs/DEPLOY.md`, `docs/MONITORING.md`, `docs/ASSETS.md`, `docs/PROTOCOL.md`, and `docs/CONTENT_PLAN.md`. Keep them in pt-BR and update the protocol table when adding WS message types.

## Invariants and gotchas

- Server/shared TypeScript runs in Node's strip-only mode: `enum`, `namespace`, parameter properties, and decorators throw at runtime even though `npm run lint` passes. Use `as const` objects/unions (see `MAT` in `types.ts`) and `import type` for type-only imports.
- Relative imports always include the extension (`./shared/types.ts`, `./App.tsx`). Extensionless imports break native Node execution.
- The 100-point weapon/event budget is a core internal rule, not a player choice. Route all new stats/events through `budget.ts`; tests assert budgets stay <=100 and no weapon is one-shot/overpowered. Player-facing allocation sliders do not exist.
- Dev tools are double-gated: client `import.meta.env.DEV` and server `NODE_ENV !== 'production'` (`src/shared/devMode.ts`). Never expose `dev:action` in production; `server/devMode.test.ts` enforces the gate.
- `vite.config.ts` intentionally supports disabling HMR/watch with `DISABLE_HMR=true` for automated edit environments. Keep that branch working.
- Env (server/VPS): `PORT` (default 3000), `HOST` (default `0.0.0.0`), `NODE_ENV`, `SERVE_CLIENT`, `CORS_ORIGINS`, `PROMPT_LEDGER_DB_PATH`, `DISABLE_HMR`. `server.ts` loads `dotenv/config`, which reads `.env`; `.env.local` is not loaded. `GEMINI_API_KEY` and `VOXELFORGE_DB_PATH` are for the offline tools under `tools/`, never for the server.
- Env (client/Vercel): `VITE_API_URL`, `VITE_WS_URL`. Vite inlines them at build time, so changing them requires a new Vercel deploy. Never put secrets in `VITE_*` variables.
- Cross-origin production: the frontend on Vercel calls the VPS directly. `CORS_ORIGINS` gates HTTP CORS and, when non-empty, the WebSocket `Origin`. Wildcards like `https://*.vercel.app` are supported. An HTTPS frontend requires `wss://`; Vercel does not proxy WebSockets.
- `vercel.json` deliberately overrides the install command to `npm install --legacy-peer-deps`; changing dependencies/scripts must keep the Vercel build working.
- Tests must stay offline: `tools/aiGenerator.test.ts` blanks `GEMINI_API_KEY` and uses `:memory:` SQLite deliberately. `server/catalog.test.ts` validates the catalog artifact and resolver determinism; `server/assets.test.ts` validates the manifest and catalog asset references; `server/ledger.test.ts` uses `:memory:` SQLite; `server/ledgerFlow.test.ts` injects a memory ledger into `RoomManager`; `server/usageReport.test.ts` covers usage aggregation. `RoomManager` accepts `{ devEnabled, ledger }` and `SocketLike`; these are the test seams.
- World units: integer voxel grid with `VOXEL_SIZE = 0.3125`, `CHUNK_SIZE = 16`, `WATER_LEVEL_VOXEL = 10` (`src/shared/types.ts`). Room size scales with 4–14 target players.
- Keep new user-facing strings in pt-BR. The ~6.6 MB Babylon chunk warning during `npm run build` is expected.
